## A. Executive summary

**Overall condition: very good engineering, not yet launchable for content reasons.** The site is a static Astro 7 build served by Cloudflare Workers static assets, plus one small Worker for the contact form. Every automated check I could run passes, and my own wider sweeps found no functional bug, no accessibility violation and no layout overflow:

- `npm run verify`: `astro check` 0 errors on 146 files, 691 unit tests and 89 Worker tests pass, the build makes 18 pages, links are clean (measured).
- `npm run test:e2e`: 135 passed, 5 skipped, in Chrome, Firefox and WebKit (measured).
- 18 pages × 9 viewport widths (320 to 1920 px): no horizontal scroll, no console error, no target under 24×24 px. axe (WCAG 2.0/2.1/2.2 A and AA plus best practice) reports **0 violations** on all 18 pages at 320, 390 and 1440 px (measured).
- Lighthouse 13.5 scores 100 in all four categories on 5 pages, mobile and desktop. Mobile LCP is 1.36 to 1.41 s, CLS 0, TBT 0 (measured, simulated throttling, local server).
- The contact journey works end to end with and without JavaScript, including the error paths, rate limit, honeypot and cross-site rejection (measured against the local Worker).

**Launch is blocked, by design.** `check:launch` refuses with 24 reasons: placeholder domain, PFA data (#1, #2), retention period (#17), Cloudflare DPF date (#22), and no page approved yet. That gate works as intended.

**Most serious problems (none critical):**
1. **A-01 (P2).** The browser checks (axe, CSP, 320 px, per-page basics) aren't part of `npm run deploy`, and there's no CI. Today's clean result depends on someone running `qa:page` page by page.
2. **A-02 (P2).** If form delivery breaks in production, nobody finds out. The Worker keeps no logs, and the only check is a manual monthly test email.
3. **A-03 (P2, known as UI-01).** On phones, inner pages spend the first 375 to 455 px on the header, the trains button, the band and the breadcrumbs before the H1 ends.
4. **A-04 (P2, known as UX-01).** The production build has no proof of work: no project, no photo, no profile link, no testimonial. For a consultant whose goal is quote requests, this is the biggest conversion gap. It depends on Alex's content.

**Strengths worth keeping:**
- Progressive enhancement: everything works without JavaScript. JS adds about 1 KB inline and is used only for the trains and the form.
- Privacy: no cookies, no third-party requests, no analytics, CSP with script and style hashes, `frame-ancestors 'none'`, HSTS.
- The form Worker validates with the same rules as the browser (`src/form-rules.ts`), blocks email-header injection, rate-limits by IP and caps the body at 64 KB.
- Single sources of truth: domain, services, form rules, colour tokens, page titles.
- A real launch gate (`check:launch`), a placeholder registry and an approval registry.

**Most valuable improvements, in order:** add browser QA to the deploy gate (A-01), add a privacy-neutral weekly heartbeat email so a broken pipeline shows up (A-02), make the mobile threshold of inner pages shorter (A-03), then publish the szitrans case study and add a photo and profile (A-04) as soon as Alex's content is ready.

**Key decisions found in code and docs:** static first, no framework runtime; no cookies or third parties (privacy policy depends on it); one Worker only for the form; colour per service group; Romanian identifiers; decisions numbered in the spec (`docs/superpowers/specs/2026-10-21-site-alex-ionescu-design.md`) and cited in comments; launch only when the registry and approvals allow it.

**Dependencies:** runtime `astro` 7.4.1, `@astrojs/sitemap` 3.7.4, `mimetext` 3.0.28. Everything else is dev tooling (wrangler 4.152.0, vitest 5.0.5, Playwright 1.64.1, Lighthouse 13.5.0, axe 4.14.0, TypeScript 6.0.3). `npm audit --omit=dev`: 0 vulnerabilities.

## F. UI/UX improvement plan

Judged from the running site (in-app browser and Playwright screenshots at 320, 375, 390, 768, 1280, 1440 and 1920 px), read through the Design Council's five lenses.

| Lens | Score | What drives it |
|---|---|---|
| Ive: material truth | 4/5 | Square corners, one honest typeface, the metro map as the brand's material. The dimmed lines (35 % on `--noapte`) turn yellow into olive, which reads as "disabled" rather than "other lines". |
| Rams: economy | 3/5 | The decorative band, trains, line drawing and its own pause control repeat on every inner page; on phones they cost about 150 px before the H1. |
| Hadid: flow | 3/5 | Home's threshold is strong (map, plaque, CTA in the first screen). Inner pages on phones begin with three bands of chrome; long service pages (about 6,000 px at 375) have a CTA only at the top and the bottom. |
| Ingels: delight | 4/5 | The metro metaphor does two jobs (navigation map and brand); the segment-to-band view transition is a nice discovery. |
| Norman: clarity | 4/5 | Clear affordances, whole-row links, visible focus on dark and light. Colour meaning collides (A-14); native-only form errors (A-08). |

**Tension to name:** Rams against Ingels on the inner-page band. The resolution: keep the delight where it pays (home, desktop bands) and make it quiet where space is scarce (phones).

### J.1 A-01: whole-site browser QA in the deploy gate

**Files:** new `tests/e2e/toate-paginile.spec.ts`; `package.json` (`deploy`).
**Approach:** read the page list from the built sitemap at runtime, so nothing is listed twice, then add the noindex pages. Reuse the existing helpers.

```ts
// tests/e2e/toate-paginile.spec.ts
// Verificările de bază pe toate paginile construite (A-01): fără derulare orizontală, axe, zone de atingere și CSP,
// la 320 și la 1440px. Lista vine din sitemap, plus paginile noindex, care lipsesc din el.
import { axe, expect, faraDerulareOrizontala, incalcariCsp, test, zoneAtingereMici } from './helpers';

const NOINDEX = ['/contact/multumim/', '/contact/eroare/', '/contact/prea-multe-linkuri/', '/nu-exista/'];

test('toate paginile trec verificările de bază', async ({ page, request }) => {
  test.skip(test.info().project.name !== 'chrome', 'o singură rulare, în Chrome');
  const xml = await (await request.get('/sitemap-0.xml')).text();
  const cai = [...xml.matchAll(/<loc>([^<]+)<\/loc>/g)].map((m) => new URL(m[1]!).pathname).concat(NOINDEX);
  for (const latime of [320, 1440]) {
    await page.setViewportSize({ width: latime, height: 800 });
    for (const cale of cai) {
      await page.goto(cale);
      await page.evaluate(() => document.fonts.ready);
      expect.soft(await faraDerulareOrizontala(page), `${cale} la ${latime}px: derulare orizontală`).toBe(true);
      expect.soft(await axe(page), `${cale} la ${latime}px: axe`).toEqual([]);
      expect.soft(await zoneAtingereMici(page), `${cale} la ${latime}px: zone sub 44px`).toEqual([]);
      expect.soft(await incalcariCsp(page), `${cale} la ${latime}px: CSP`).toEqual([]);
    }
  }
});
```
